# Local AI Bench v0.3.0 — Mac 驗證紀錄

測試裝置：Apple M2 Max、12 核 CPU、96 GiB RAM、macOS 26.5.2。

## 已完成的功能

- Hugging Face 即時熱門 GGUF 目錄、搜尋、中小模型與容量排序、版本／大小／授權檢視。
- 固定 commit 下載、可見的真實進度、取消、檔案大小及 SHA-256 校驗，成功後加入 GUI 佇列。
- 本機硬件偵測、容量預算、本機標準報告證據與可選的現有社群 leaderboard 讀取。
- 繁體中文新介面、app icon、GUI 階段及樣本進度、即時測量、完成自動捲至結果、歷史報告。
- 網上目錄與 runtime 路徑偏好保存；離線模式不載入網上推薦。

## 驗證

- 17 個 Python 測試通過，包括順序執行、取消及 stdout 關閉仍能清理模型程序。
- 9 個 Swift 單元測試通過：dense/MoE 限制、metadata 不一致、RAM 預算、單檔／checksum 要求、離線狀態、佇列驗證。
- 1 個真實 Hugging Face 整合測試通過：即時 Top 10、搜尋 MiniCPM、固定 revision 檔案資料、實際下載進度、取消、重新下載 1.56 GB 及 SHA-256 校驗。整個 Swift 套件合計 10/10 通過。
- GUI 直接執行真實 MiniCPM5-2B 完整 workload，保留 6 個樣本；畫面擷取確認中途 3/6 及最終 6/6 並展示實際數值。不是用 fixture 當硬件測試。
- GUI Stop handler、退出時的 AppKit delegate，以及完整完成流程由 `Packaging/smoke-gui.py` 以同一 app 的明確 QA 參數觸發；檢查狀態、報告與子程序清理。這是實際視窗／控制器執行，不聲稱使用 Accessibility 點擊所有按鈕或檔案對話框。

## 本次測試修正

- 改用 URLSessionDownloadDelegate 的實際下載 session，解決 async convenience API 沒有提供可用進度 callback。
- 修正退出時 AppKit 巢狀事件迴圈阻塞 SwiftUI 清理：先讓 runner 關閉並回報，再完成退出。
- 在 runner finally 中，即使 UI 關閉 stdout，仍然優先清理 llama-server。

## 仍有明確限制

- 社群 API 已接入，但既有網站 owner-private；本次回應無法作為已授權 JSON 資料使用。畫面正確顯示社群實測暫不可用。沒有新增 native OAuth、沒有更改網站 audience、沒有上傳報告。
- 容量推薦是 4K context 初篩；沒有用估算生成假速度、品質評分或聲稱所有新架構可由目前 runtime 載入。
- 只有 MiniCPM 做真實推理；三個不同真模型的依次執行仍由合成程序測試覆盖，沒有額外下載兩個大模型。
- macOS Apple Silicon 版本；Windows/Linux app 未實作。
- `.dmg` 使用 ad-hoc signing，未 Developer ID 簽署或 notarize。Python、llama.cpp、模型權重仍為外部依賴。
