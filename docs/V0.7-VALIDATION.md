# TokFire Bench 0.7 validation — 16 September 2026

## Actual local inference

Host: Apple M2 Max, 12 CPU cores, 96 GiB unified RAM, macOS 26.5.2.
Model: official MiniCPM5-2B Q4_K_M GGUF, SHA-256
`ec2d5801640099e97d8d7e8003ad4d81f336e757811f03a26173dddf386602fd`.
Runtime: installed Homebrew llama-server; report stores its binary SHA-256.

One short-chat sweep, one excluded warm-up, three measured rounds per level:

| Concurrent jobs | Completed jobs | Median request decode | Median first output | Median aggregate |
|---|---:|---:|---:|---:|
| 1 | 3/3 | 36.4 tok/s | 804 ms | 33.3 tok/s |
| 2 | 6/6 | 21.9 tok/s | 1,507 ms | 37.9 tok/s |
| 3 | 9/9 | 23.2 tok/s | 1,469 ms | 60.5 tok/s |

All produced visible answers. One job met the configured interactive guideline in
this sweep; 2/3-job levels had slower requests. None met 100 tok/s for every request.
This is a short run on a working Mac, not a thermally controlled hardware review.

The real agent fixture completed **0/3** tasks with this small model: JSON/tool
protocol failures were retained and reported as failures despite fast token output.
This does not establish general agent quality; it tests only the fixed local task.

A separate packaged Mac GUI run completed 3/3 short-chat jobs, displayed live
progress, saved JSON/Markdown and showed workload results (median decode 43.6 tok/s,
first output 690 ms). Observed variation reinforces that these are individual runs,
not guaranteed hardware scores. Upload was disabled for these UI trials.
